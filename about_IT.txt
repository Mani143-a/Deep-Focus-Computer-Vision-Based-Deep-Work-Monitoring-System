DeepFocus Project Handoff: Stage 3.1
1. Project Overview

Project name: DeepFocus

Goal: Build a first-person study/deep-work monitoring system using Python, OpenCV, MediaPipe, and computer vision.

The system monitors a person through a camera while they study/work and attempts to detect:

Face presence
Eye openness/closure
Drowsiness
Long periods of closed eyes
Loss of face from camera
Focus state
Session duration
FPS
Eye Aspect Ratio, or EAR
Warning events

The long-term goal is to evolve DeepFocus into a deep-work productivity monitoring system, rather than simply an eye detector.

4. Video Source

5. Face Landmark Detection

The project uses:

LandmarkDetector

from:

app.vision.landmarks

The detector processes each frame:

faces = self.landmark_detector.process(frame)

The result contains detected face landmarks.

The first detected face is currently used:

if faces:
    face = faces[0]

The project also has:

draw_landmarks(frame, faces)

for visual debugging.

This allows us to see whether MediaPipe is correctly detecting the face.

6. Eye Detection

Eye metrics are calculated using:

calculate_eye_metrics(face)

from:

app.vision.eye_metrics

The important metric currently used is:

EAR

Eye Aspect Ratio.

The resulting value is:

eye_metrics.average_ear

and stored in:

self.current_ear

The current threshold is:

ear_threshold=0.20

Conceptually:

EAR high
    ↓
Eyes open

EAR decreases
    ↓
Eyes closing

EAR below threshold
    ↓
Eyes considered closed

The exact threshold will eventually need calibration because EAR varies between people, camera angles, lighting conditions, and landmark quality.

7. Focus Monitoring State Machine

The monitoring logic is abstracted into:

FocusMonitor

from:

app.monitoring.state

with:

FocusState
MonitorConfig

Current configuration:

MonitorConfig(
    ear_threshold=0.20,
    drowsy_duration=1.5,
    no_face_duration=2.0,
)

Therefore:

EAR < 0.20
    ↓
Eyes considered closed

Eyes closed for approximately 1.5 seconds
    ↓
DROWSY state / warning condition

The current UI recognizes at least:

NO_FACE

DROWSY

There may be additional states depending on the implementation of state.py.

9. FPS Tracking

There is a dedicated:

FPSTracker

class.

It calculates instantaneous FPS and applies smoothing.

Current default:

smoothing=0.9

The idea is:

instantaneous FPS
       ↓
exponential smoothing
       ↓
stable displayed FPS

This avoids the overlay jumping wildly between FPS values.

The FPS is displayed on screen.

12. Audio Warning

We recently fixed an important bug.

The application calls:

if result.warning:
    self._play_warning()

The method is now correctly implemented as a class method:

def _play_warning(self) -> None:
    """Play an audible warning when drowsiness is detected."""

    winsound.Beep(1000, 500)

The import is:

import winsound

This means the application should produce:

1000 Hz
500 ms

Windows beep when the warning condition is triggered.

13. Important Bug We Fixed

Originally, _play_warning() was accidentally inserted inside _run_loop().

Incorrect:

def _run_loop(self):

    ...

    def _play_warning(self):
        winsound.Beep(1000, 500)

That creates a local nested function.

It does NOT create:

DeepFocusApp._play_warning

Therefore this:

self._play_warning()

produced:

'DeepFocusApp' object has no attribute '_play_warning'

The correct structure is:

class DeepFocusApp:

    def _run_loop(self):
        ...

    def _play_warning(self):
        ...

    def _draw_overlay(self):
        ...

    def shutdown(self):
        ...

This was a Python indentation/scope problem, not a computer vision problem.

The important part of the processing loop is currently:

    result = self.monitor.update(

)

This is currently the core DeepFocus pipeline.

17. Current Known Weakness

There is one issue we should investigate next.

Currently:

if result.warning:
    self._play_warning()

is executed every frame where:

result.warning == True

If FocusMonitor keeps warning=True for multiple frames, the application may produce:

BEEP
BEEP
BEEP
BEEP
BEEP
...

at camera frame rate.

That is not desirable.

We don't want a continuous machine-gun beep.

We want something like:

Eyes closed
    ↓
1.5 seconds
    ↓
DROWSY
    ↓
BEEP
    ↓
wait
    ↓
still drowsy
    ↓
